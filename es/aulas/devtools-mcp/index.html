Clase 3 · 15 min

Chrome DevTools MCP: ver lo que hizo el agente (consola, red)

Cuando el agente dice "no pude", la respuesta suele estar en la consola o en la red: un archivo que dio 404, un error de JavaScript. El Chrome DevTools MCP le da al agente las mismas pestañas que tú abres con F12. En esta clase listas la consola y la red de la página del kit, encuentras el error plantado y lo dejas en cero.

Comenzar la lección

En esta lección vas a

  1. 1list_console_messages y list_network_requests
  2. 2El error plantado: promocoes.json que da 404
  3. 3Telemetría activada por defecto y cómo desactivarla
  4. 4pageId, sandbox y las otras trampas de la 1.10.1

Objetivo: ver por el Chrome DevTools MCP la consola y la red de la página que abrió el agente, encontrar el error y dejarlo en cero en una copia corregida.

01 · El F12 del agente

Haz clic en cada bloque.

Haz clic en cada bloque del diagrama para ver lo que hace.

La página parece correcta. La consola y la red muestran que falta un archivo.

02 · ¿Playwright MCP o DevTools MCP?

Uno actúa, el otro investiga.

1. Para actuar

Rellenar, hacer clic y esperar usando el árbol de accesibilidad, con refs. Playwright MCP también lista la consola y la red (browser_console_messages, browser_network_requests), pero su fuerte es la tarea.

En la clase 2 ya avisaba: "Console: 1 errors".

2. Para investigar

Consola con nivel, cada solicitud con su estado, traza de rendimiento y Lighthouse. Es el servidor para preguntar "¿por qué falló?".

Los dos pueden quedar conectados al mismo agente: el configurar.mjs de la clase 2 ya escribió ambos en el .mcp.json.

3. Trampas de la 1.10.1

Telemetría: por defecto el servidor envía estadísticas de uso a Google y manda URLs de trazas de rendimiento a la API de CrUX. El kit lo desactiva con --no-usage-statistics y --no-performance-crux.

Toda herramienta de página pide pageId (tómalo de list_pages). Con el Chromium de Playwright, pasa --chromeArg=--no-sandbox, que es el valor por defecto de Playwright; sin eso el navegador se cierra con "Target closed".

Versión nuevaLa 1.11.0 salió el 15/10/2026 y no se probó aquí. El propio servidor avisa "Update available"; el kit se queda en la 1.10.1 hasta la próxima captura.

03 · Encontrar el error y dejarlo en cero

El devtools.mjs abre la página inicial del kit y lista consola y red. La corrección se ejecuta en una copia, sin tocar el kit.

Terminal · consola y red de la página del kit
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node devtools.mjs; echo "saída: $?"
Terminal · corregir en una copia y comprobar
cd ~/projetos/formacao-webmcp-navegador-v72/kit
E=${TMPDIR:-/tmp}/kit3-aula3; rm -rf "$E"; cp -r site "$E"
echo '{"texto": "Revisão básica com 10% de desconto em novembro."}' > "$E/promocoes.json"
SITE="$E" node devtools.mjs; echo "saída: $?"

04 · Práctica

El error del kit y tu sitio.

E1 · Encontrar el 404

5 min

Ejecuta el primer bloque. Abre kit/site/index.html y encuentra la línea que pide el archivo que falta.

Listo cuando: node devtools.mjs → erros no console: 2 · requisições: 3 · com falha: 1 y saída: 1.

E2 · Dejar en cero en la copia

10 min

Ejecuta el segundo bloque. Después cambia el texto del promocoes.json de la copia y comprueba que la página muestra el texto nuevo.

Listo cuando: SITE=/tmp/kit3-aula3 node devtools.mjs → erros no console: 0 · requisições: 3 · com falha: 0 y saída: 0.

E3 · La consola de tu sitio

10 min

Ejecuta el devtools.mjs con la dirección de un sitio tuyo. Por cada error, anota si el agente perdería algo por culpa de él.

Listo cuando: node devtools.mjs con la dirección de tu sitio → línea erros no console: N · requisições: M · com falha: F, con N y F anotados.
