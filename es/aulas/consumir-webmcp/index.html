Clase 4 · 20 min

El agente que consume WebMCP: descubrimiento, ejecución, exposedTo y origen

El curso 2 enseña a la página a registrar herramientas. Aquí te quedas del otro lado: el agente. El Playwright MCP 0.0.83 ya convierte las herramientas WebMCP de la página en herramientas propias, con las anotaciones y un aviso de "no confiable". Ves el descubrimiento, la llamada, el camino sin la API y quién ve qué entre orígenes. Experimental al 19/10/2026.

Comenzar la lección

En esta lección vas a

Objetivo: ver cómo un agente descubre y llama herramientas WebMCP, qué cambia sin la API y quién ve qué entre orígenes.

02 · Cuatro cosas que mostró el ensayo

Chromium 156.0.8078.4 de Playwright 1.64.0, flag de prueba, 19/10/2026.

1. Nativo y sin

El kit activa la API con --enable-features=WebMCPTesting, que por el nombre equivale a la flag chrome://flags/#enable-webmcp-testing de la documentación. Experimental: Chrome Status dice "Proposed" y el origin trial va de Chrome 149 a 156.

Sin la flag, tools/list se queda con 25 herramientas y el agente encuentra el formulario en el árbol. Es la prueba de fallback que todo sitio con WebMCP necesita pasar.

2. Con token de verdad

En la clase 2, el mismo Chromium vio las 8 herramientas de inema.club sin ninguna flag: el sitio tiene token de origin trial y Chromium 156 está dentro del trial.

Playwright lee document.modelContext ?? navigator.modelContext: el segundo es el nombre antiguo (antes del PR #177, aceptado el 19/05/2026), que la herramienta todavía acepta. No lo uses en código nuevo.

3. Origen e iframe

Cada documento solo lista, en getTools(), las herramientas que él mismo registró, con o sin exposedTo. Un iframe de otro origen sin allow="tools" ni siquiera puede registrar: NotAllowedError por la permissions policy.

En cambio, el agente de automatización (Playwright MCP) vio las herramientas de todos los frames, incluida la que no tiene exposedTo.

Lectura honestaLa spec dice que, por defecto, la herramienta es visible para la propia página, para páginas del mismo origen y para agentes integrados en el navegador; exposedTo amplía eso. El build puede diferir de la spec: vale lo que muestre tu prueba, con versión y fecha.

4. Dato, no instrucción

El nombre, la descripción y la respuesta de la herramienta vienen de la página, y Playwright le avisa al modelo de eso en cada llamada. Una página maliciosa puede escribir instrucciones en la descripción.

La amenaza, la confirmación y exposedTo como defensa son del curso 4.

04 · Quién ve qué entre orígenes

Vitrine en el origen A (kit/site) con un widget de envío en el origen B (kit/site-widget, otro puerto).

Terminal · orígenes e iframes
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node origens.mjs; echo "saída: $?"
Fragmento de kit/site/vitrine.html
const f = document.createElement('iframe');
if (q.get('allow') !== '0') f.allow = 'tools';            // permissions policy "tools": sin ella, el iframe no puede usar la API
f.src = `${q.get('widget')}?topo=${encodeURIComponent(location.origin)}`;
Ejemplo del repositorio
Chromium 156.0.8078.4 (Playwright) · modo: nativo · spec de 16/10/2026
1. vitrine (origem A) · getTools(): consultar_vitrine
2. widget (origem B, allow="tools") · registro: registrou 2 · getTools(): widget_exposto, widget_privado
3. widget sem allow="tools" · registro: NotAllowedError: Access to the feature "tools" is disallowed by permissions policy.
4. Playwright MCP 0.0.83 (agente de automação, todos os frames) · vê: webmcp_consultar_vitrine, webmcp_widget_exposto, webmcp_widget_privado
saída: 0

Líneas 1 y 2: cada documento lista solo las suyas. Línea 3: sin allow="tools", el widget de otro origen recibe NotAllowedError. Línea 4: el agente de automatización ve las tres, de todos los frames.
