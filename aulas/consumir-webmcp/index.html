Aula 4 · 20 min

O agente que consome WebMCP: descoberta, execução, exposedTo e origem

O curso 2 ensina a página a registrar ferramentas. Aqui você fica do outro lado: o agente. O Playwright MCP 0.0.83 já transforma as ferramentas WebMCP da página em ferramentas dele, com as anotações e um aviso de "não confiável". Você vê a descoberta, a chamada, o caminho sem a API e quem enxerga o quê entre origens. Experimental em 19/10/2026.

Começar a aula

Nesta aula você vai

  1. 1Descoberta: webmcp_consultar_horarios aparece na lista do agente
  2. 2Anotações e o aviso UNTRUSTED que o agente recebe
  3. 3Sem a API: o agente volta para a tela

Objetivo: ver como um agente descobre e chama ferramentas WebMCP, o que muda sem a API e quem vê o quê entre origens.

02 · Quatro coisas que o ensaio mostrou

Chromium 156.0.8078.4 do Playwright 1.64.0, flag de teste, 19/10/2026.

1. Nativo e sem

O kit liga a API com --enable-features=WebMCPTesting, que pelo nome equivale à flag chrome://flags/#enable-webmcp-testing da documentação. Experimental: o Chrome Status diz "Proposed" e o origin trial vai do Chrome 149 ao 156.

Sem a flag, tools/list fica com 25 ferramentas e o agente acha o formulário na árvore. É o teste de fallback que todo site com WebMCP precisa passar.

2. Com token de verdade

Na aula 2, o mesmo Chromium viu as 8 ferramentas do inema.club sem flag nenhuma: o site tem token de origin trial e o Chromium 156 está dentro do trial.

O Playwright lê document.modelContext ?? navigator.modelContext: o segundo é o nome antigo (antes do PR #177, aceito em 19/05/2026), que a ferramenta ainda aceita. Não use em código novo.

3. Origem e iframe

Cada documento só lista, no getTools(), as ferramentas que ele mesmo registrou, com ou sem exposedTo. Um iframe de outra origem sem allow="tools" nem consegue registrar: NotAllowedError da permissions policy.

Já o agente de automação (Playwright MCP) viu as ferramentas de todos os frames, inclusive a sem exposedTo.

Leitura honestaA spec diz que, por padrão, a ferramenta é visível para a própria página, para páginas de mesma origem e para agentes embutidos no navegador; exposedTo amplia isso. O build pode divergir da spec: vale o que o seu teste mostrar, com versão e data.

4. Dado, não instrução

Nome, descrição e resposta da ferramenta vêm da página, e o Playwright avisa o modelo disso em toda chamada. Uma página maliciosa pode escrever instrução na descrição.

Ameaça, confirmação e exposedTo como defesa são do curso 4.

04 · Quem vê o quê entre origens

Vitrine na origem A (kit/site) com um widget de frete na origem B (kit/site-widget, outra porta).

Terminal · origens e iframes
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node origens.mjs; echo "saída: $?"
Trecho de kit/site/vitrine.html
const f = document.createElement('iframe');
if (q.get('allow') !== '0') f.allow = 'tools';            // permissions policy "tools": sem ela, o iframe não usa a API
f.src = `${q.get('widget')}?topo=${encodeURIComponent(location.origin)}`;
Exemplo do repositório
Chromium 156.0.8078.4 (Playwright) · modo: nativo · spec de 16/10/2026
1. vitrine (origem A) · getTools(): consultar_vitrine
2. widget (origem B, allow="tools") · registro: registrou 2 · getTools(): widget_exposto, widget_privado
3. widget sem allow="tools" · registro: NotAllowedError: Access to the feature "tools" is disallowed by permissions policy.
4. Playwright MCP 0.0.83 (agente de automação, todos os frames) · vê: webmcp_consultar_vitrine, webmcp_widget_exposto, webmcp_widget_privado
saída: 0

Linhas 1 e 2: cada documento lista só as dele. Linha 3: sem allow="tools", o widget de outra origem recebe NotAllowedError. Linha 4: o agente de automação vê os três, de todos os frames.

05 · Prática

Os dois modos e as origens. Cada exercício tem um "pronto quando".

E1 · Com a API

10 min

Rode o modo nativo. Ache na saída as duas anotações e o aviso UNTRUSTED. Diga por que o script não chama webmcp_agendar_revisao.

Pronto quando: node consumir.mjs nativo → horários: 09:30, 11:30, 15:30, 16:30 e saída: 0.

E2 · Sem a API

5 min

Rode o modo sem. Compare o número de ferramentas com o do E1.

Pronto quando: node consumir.mjs sem → 25 ferramentas do navegador + 0 da página e formulário na árvore: sim, saída: 0.

E3 · Origens

10 min

Rode o origens.mjs. Depois abra kit/site-widget/index.html, tire o exposedTo do widget_exposto e rode de novo: a linha 4 muda?

Pronto quando: node origens.mjs → linha 3. widget sem allow="tools" · registro: NotAllowedError e saída: 0, com a resposta da pergunta anotada.
