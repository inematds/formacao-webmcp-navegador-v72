Lesson 3 · 15 min

Chrome DevTools MCP: see what the agent did (console, network)

When the agent says "I couldn't do it," the answer is usually in the console or the network: a file that returned 404, a JavaScript error. Chrome DevTools MCP gives the agent the same tabs you open with F12. In this lesson you list the console and the network of the kit page, find the planted error, and bring it to zero.

Start the lesson

In this lesson you will

  1. 1list_console_messages and list_network_requests
  2. 2The planted error: a promocoes.json that returns 404
  3. 3Telemetry is on by default, and how to turn it off
  4. 4pageId, sandbox, and the other gotchas in 1.10.1

Goal: use Chrome DevTools MCP to see the console and network of the page the agent opened, find the error, and bring it to zero in a fixed copy.

02 · Playwright MCP or DevTools MCP?

One acts, the other investigates.

1. To act

Fill in, click, and wait using the accessibility tree, with refs. Playwright MCP also lists console and network (browser_console_messages, browser_network_requests), but its strength is the task.

2. To investigate

Console with levels, every request with its status, performance traces, and Lighthouse. It's the server to ask "why did it fail?".

Both can stay connected to the same agent: lesson 2's configurar.mjs already wrote both into .mcp.json.

3. Gotchas in 1.10.1

Telemetry: by default the server sends usage statistics to Google and sends performance trace URLs to the CrUX API. The kit turns this off with --no-usage-statistics and --no-performance-crux.

Every page tool needs a pageId (get it from list_pages). With Playwright's Chromium, pass --chromeArg=--no-sandbox, which is the Playwright default; without it the browser closes with "Target closed".

New versionVersion 1.11.0 came out on 10/15/2026, according to the npm registry, and was not tested here. The server itself warns "Update available"; the kit stays on 1.10.1 until the next capture.

03 · Find the error and bring it to zero

devtools.mjs opens the kit's home page and lists the console and network. The fix runs on a copy, without touching the kit.

Terminal · console and network of the kit page
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node devtools.mjs; echo "saída: $?"
Terminal · fix in a copy and check
cd ~/projetos/formacao-webmcp-navegador-v72/kit
E=${TMPDIR:-/tmp}/kit3-aula3; rm -rf "$E"; cp -r site "$E"
echo '{"texto": "Revisão básica com 10% de desconto em novembro."}' > "$E/promocoes.json"
SITE="$E" node devtools.mjs; echo "saída: $?"
Example from the repository
→ navigate_page {"url":"http://127.0.0.1:PORTA/","pageId":1}
→ list_console_messages {"pageId":1}
  [error] Failed to load resource: the server responded with a status of 404 (Not Found)
  [error] promoções: falha ao carregar promocoes.json (HTTP 404)
→ list_network_requests {"pageId":1}
  GET http://127.0.0.1:PORTA/ [200]
  GET http://127.0.0.1:PORTA/estilo.css [200]
  GET http://127.0.0.1:PORTA/promocoes.json [404]
erros no console: 2 · requisições: 3 · com falha: 1
saída: 1

Two console errors (the browser's 404 and the page's own message) and one failed request. On screen, the page only says "Sem promoções no momento".

→ navigate_page {"url":"http://127.0.0.1:PORTA/","pageId":1}
→ list_console_messages {"pageId":1}
→ list_network_requests {"pageId":1}
  GET http://127.0.0.1:PORTA/ [200]
  GET http://127.0.0.1:PORTA/estilo.css [200]
  GET http://127.0.0.1:PORTA/promocoes.json [200]
erros no console: 0 · requisições: 3 · com falha: 0
saída: 0

The SITE variable swaps the served folder for the copy in /tmp/kit3-aula3, which has the promocoes.json. Zero errors, zero failures, exit 0.
