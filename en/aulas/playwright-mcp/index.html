Lesson 2 · 20 min

Playwright MCP in Claude Code/Codex: the accessibility snapshot in practice

Playwright MCP gives your coding agent a browser. It doesn't send a screenshot: it sends the accessibility snapshot, with a reference (ref) on each control, and the agent acts through those refs. In this lesson a script makes exactly the calls the agent would make, without a model, and then you connect the server to Claude Code or Codex.

Start the lesson

In this lesson you will

  1. 1The snapshot with refs (e13, e15, e18)
  2. 2The calls: navigate, snapshot, type, select, click, wait_for
  3. 3The common mistake: taking the snapshot before the page has finished loading
  4. 4Connect to Claude Code (.mcp.json) and Codex (config.toml)

Goal: do with Playwright MCP what the agent does: read the snapshot, find the control by its ref and act, and connect the server to your agent.

02 · What the agent receives and what it does

Reading the dry-run output.

1. The tools

The server exposes 25 browser tools (browser_navigate, browser_snapshot, browser_click, browser_type, browser_select_option, browser_wait_for, browser_console_messages…). The agent sees them all in the list and chooses.

The project's documentation today also recommends a CLI-and-skills route for coding agents; the kit uses the tools over MCP, which is what Claude Code and Codex read.

2. Refs, not coordinates

In the dry run, the script found textbox "Seu nome" = e13, combobox "Serviço" = e15 and button "Ver horários" = e18 and acted through them. No pixels.

That's why the HTML from course 0 matters: the label becomes the name, and the name is how the agent finds the ref.

3. Wait for the proof

The times arrive 1.5 s after the click. With browser_wait_for waiting for the text "horários livres para", the snapshot comes back complete. Without waiting, you get "Carregando horários…" and zero times.

Wait for the text that proves the result, not for a number of seconds.

Who pays for the mistakeAn agent that takes the snapshot too early answers "there are no times" with full confidence. Lesson 7 comes back to this case.

03 · The dry run: the agent's calls, without a model

ver-como-agente.mjs connects Playwright MCP over stdio, the way Claude Code would, and does the task "see the times for Revisão completa".

Terminal · do the task through Playwright MCP
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node ver-como-agente.mjs; echo "saída: $?"
Terminal · the same, without waiting for the list
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node ver-como-agente.mjs --sem-esperar; echo "saída: $?"
Example from the repository
→ browser_navigate {"url":"http://127.0.0.1:PORTA/agendar.html"}
→ browser_snapshot {}
  achei: textbox "Seu nome" = e13 · combobox "Serviço" = e15 · button "Ver horários" = e18
→ browser_type {"target":"e13","text":"Ana"}
→ browser_select_option {"target":"e15","values":["Revisão completa"]}
→ browser_click {"target":"e18"}
→ browser_wait_for {"text":"horários livres para"}

tarefa: horários de Revisão completa em 2026-11-03 → 2 (08:00, 13:00) em 7 chamadas
saída: 0

Seven calls. Each line with → is a tool called by the MCP client; PORTA stands in for the local server's random port.

Without browser_wait_for, the snapshot catches "Carregando horários…". The script exits with 1, but a hurried agent would say there's no time available.

A project server stays "Pending approval" until you open claude inside kit/ and approve it; after that, /mcp shows the server connected (this step was not captured).

05 · Practice

The dry run, your site, and your agent.

10 min

10 min

Done when: claude mcp get playwright → Scope: Project config and, after you approve, Status: ✓ Connected; in Codex, the server shows up in the /mcp list.
