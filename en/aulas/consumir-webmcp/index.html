Lesson 4 · 20 min

The agent that consumes WebMCP: discovery, execution, exposedTo, and origin

Course 2 teaches the page to register tools. Here you stand on the other side: the agent. Playwright MCP 0.0.83 already turns the page's WebMCP tools into its own tools, with the annotations and an "untrusted" warning. You see the discovery, the call, the path without the API, and who sees what across origins. Experimental as of 10/19/2026.

Start the lesson

In this lesson you will

  1. 1Discovery: webmcp_consultar_horarios shows up in the agent's list

  3. 3Without the API: the agent goes back to the screen
  4. 4Iframe from another origin, allow="tools", and exposedTo

Goal: see how an agent discovers and calls WebMCP tools, what changes without the API, and who sees what across origins.

02 · Four things the dry run showed

Chromium 156.0.8078.4 from Playwright 1.64.0, test flag, 10/19/2026.

1. Native and without

The kit turns the API on with --enable-features=WebMCPTesting, which by its name matches the chrome://flags/#enable-webmcp-testing flag in the documentation. Experimental: Chrome Status says "Proposed" and the origin trial runs from Chrome 149 to 156.

Without the flag, tools/list has 25 tools and the agent finds the form in the tree. This is the fallback test every site with WebMCP needs to pass.

2. With a real token

In lesson 2, the same Chromium saw the 8 inema.club tools with no flag at all: the site has an origin trial token and Chromium 156 is inside the trial.

Playwright reads document.modelContext ?? navigator.modelContext: the second is the old name (before PR #177, accepted on 05/19/2026), which the tool still accepts. Don't use it in new code.

3. Origin and iframe

Each document lists, in getTools(), only the tools it registered itself, with or without exposedTo. An iframe from another origin without allow="tools" can't even register: NotAllowedError from the permissions policy.

The automation agent (Playwright MCP), on the other hand, saw the tools from all frames, including the one without exposedTo.

Honest readingThe spec says that, by default, a tool is visible to the page itself, to same-origin pages, and to agents embedded in the browser; exposedTo widens that. The build may differ from the spec: what your test shows is what counts, with version and date.

4. Data, not instruction

The tool's name, description, and response come from the page, and Playwright warns the model about this on every call. A malicious page can write instructions into the description.

Threat, confirmation, and exposedTo as a defense are covered in course 4.

04 · Who sees what across origins

A storefront on origin A (kit/site) with a shipping widget on origin B (kit/site-widget, another port).

Terminal · origins and iframes
cd ~/projetos/formacao-webmcp-navegador-v72/kit
node origens.mjs; echo "saída: $?"
Excerpt from kit/site/vitrine.html
const f = document.createElement('iframe');
if (q.get('allow') !== '0') f.allow = 'tools';            // permissions policy "tools": without it, the iframe can't use the API
f.src = `${q.get('widget')}?topo=${encodeURIComponent(location.origin)}`;
Example from the repository
Chromium 156.0.8078.4 (Playwright) · modo: nativo · spec de 16/10/2026
1. vitrine (origem A) · getTools(): consultar_vitrine
2. widget (origem B, allow="tools") · registro: registrou 2 · getTools(): widget_exposto, widget_privado
3. widget sem allow="tools" · registro: NotAllowedError: Access to the feature "tools" is disallowed by permissions policy.
4. Playwright MCP 0.0.83 (agente de automação, todos os frames) · vê: webmcp_consultar_vitrine, webmcp_widget_exposto, webmcp_widget_privado
saída: 0

Lines 1 and 2: each document lists only its own. Line 3: without allow="tools", the widget from another origin gets NotAllowedError. Line 4: the automation agent sees all three, from all frames.
