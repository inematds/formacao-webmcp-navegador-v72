Lesson 6 · 20 min

An agent tests your site: tasks with criteria and results saved to a file

A test that only exists in the conversation with the agent disappears when the conversation ends. Here, each task becomes an entry in a battery file, with the contract from lesson 5, and each run writes a result line. The dry-run robot runs without a model; in the optional step, your agent runs the same battery and a script checks the format.

Start the lesson

In this lesson you will

  1. 1The battery file: contract + steps + what is expected
  2. 2The dry-run robot: roles and names from the tree, no model
  3. 3resultados/*.jsonl: one line per task
  4. 4The same test with your agent, checked by format

Goal: run a task battery against the site and write the result to a file, in the dry run and with your agent.

01 · From the battery to the result file

Click each block.

Click each block in the diagram to see what it does.

The dry run tells you whether the site works. The agent tells you whether an agent can use the site. Both write to a file.

02 · Reading the result

What counts as a passing test.

1. Expected × obtained

A task passes when it ends the way the file expects: ok with the proof seen, or parou at the right signal. Task t3 passed by stopping at the login.

The script exits with 0 only if all tasks ended as expected. You can put it in CI.

2. Agent: format only

The model's response changes with every run. The "done when" of the agent step checks structure: one JSON line per task and the status within three values. Lines outside the format are counted and ignored.

Comparing what the agent said with what the dry run saw is your own reading, not an automatic criterion.

3. Who tests whom

The test agent only observes and reports: it doesn't fix the site in the middle of the test. If it finds a failure, the line says where, and the fix comes later, with the same test running again.

Only against the kit or a site of your own.

In-depth evaluationFrozen battery, regression and agent evals belong to the LOOP-R Engineering Program (verification) and to course 5 of this program.

04 · The same battery with your agent (optional)

One claude -p with the kit's Playwright MCP and only the browser tools allowed. It uses your subscription; run it once.

Terminal · your agent runs the battery
cd ~/projetos/formacao-webmcp-navegador-v72/kit
mkdir -p resultados; node servir.mjs & SRV=$!; sleep 1
node configurar.mjs > /dev/null
claude -p "$(node prompt-agente.mjs bateria.json)" --mcp-config .mcp.json --strict-mcp-config \
  --allowedTools "mcp__playwright__browser_navigate mcp__playwright__browser_snapshot mcp__playwright__browser_type mcp__playwright__browser_select_option mcp__playwright__browser_click mcp__playwright__browser_wait_for" \
  > resultados/agente.jsonl; echo "claude: saída $?"
kill $SRV
node conferir-resultados.mjs resultados/agente.jsonl bateria.json; echo "saída: $?"
Example from the repository
site do kit em http://127.0.0.1:8433/ (Ctrl+C para parar)

  t1-horarios        ok
  t2-servicos        ok
  t3-minha-conta     parou
linhas JSON válidas: 3 de 3 tarefas · linhas ignoradas: 0

In this run, the agent reached the same three statuses as the dry run and described the t3 blocker. Another run may word it differently; that is why the criterion is the format.

05 · Practice

The dry run always; the agent once. Each exercise has a "done when".

E1 · The battery as a dry run

10 min

Run the battery. Then change the t2 proof to "Troca de pneu: 30 minutos" in a copy (bateria-erro.json) and run the copy.

Done when: node rodar-bateria.mjs bateria.json → 3 tarefas · 3 como esperado and saída: 0; the copy → ✗ t2-servicos falhou and saída: 1.

E2 · Your agent (optional)

15 min

With Claude Code installed, run the agent block once. In Codex, build the request with node prompt-agente.mjs bateria.json and run it with the servers from config.toml.

Done when: node conferir-resultados.mjs resultados/agente.jsonl bateria.json → linhas JSON válidas: 3 de 3 tarefas and saída: 0.
